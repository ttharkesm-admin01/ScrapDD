# ระบบขายเศษวัสดุเหลือใช้ — TKF

หน้าเว็บอยู่บน **GitHub Pages** (public เสมอ) ส่วนข้อมูล รหัสผ่าน และการตรวจสิทธิ์ทั้งหมดอยู่ที่
**Google Apps Script + Google Sheets + Google Drive** ซึ่งเป็นบัญชีของคุณเท่านั้น

```
เบราว์เซอร์ ── fetch ──▶ Apps Script (ตรวจ token + บทบาท) ──▶ Sheets / Drive
   (GitHub Pages)                 ▲ ข้อมูลอยู่ฝั่งนี้ทั้งหมด
```

---

## ติดตั้ง 1 ครั้ง

### 1. สร้างหลังบ้าน

1. สร้าง Google Sheet ใหม่ในบัญชีธุรการ ตั้งชื่อ `TKF-ScrapSales-DB`
2. เมนู **ส่วนขยาย → Apps Script**
3. ลบโค้ดเดิมทิ้ง แล้ววางเนื้อหาไฟล์ `backend/Code.gs`
4. กด ⚙️ **การตั้งค่าโปรเจกต์ → แสดงไฟล์ appsscript.json** แล้ววางเนื้อหาไฟล์ `backend/appsscript.json`
5. เลือกฟังก์ชัน `setup` แล้วกด **เรียกใช้** → อนุญาตสิทธิ์ → จะขึ้นกล่องบอกรหัสผ่านเริ่มต้น

ระบบจะสร้างชีต `users / sessions / fields / records / files / audit` ใส่หัวข้อ 26 รายการจาก AppSheet เดิม
และสร้างบัญชี `admin` / `ChangeMe2026!`

### 2. Deploy เป็นเว็บแอป

**ทำให้เข้าถึงได้ → ติดตั้ง → ประเภท: เว็บแอป**

| ช่อง | ต้องเลือก |
|---|---|
| ดำเนินการในฐานะ | **ฉัน (บัญชีธุรการ)** |
| ผู้มีสิทธิ์เข้าถึง | **ทุกคน** |

> "ทุกคน" หมายถึงเรียก URL ได้โดยไม่ต้องมีบัญชี Google — นี่คือสิ่งที่ทำให้ login แบบธรรมดาเป็นไปได้
> ความปลอดภัยมาจาก token ในโค้ด ไม่ใช่จากการซ่อน URL

คัดลอก URL ที่ลงท้าย `/exec` เก็บไว้

### 3. ขึ้น GitHub Pages

1. สร้าง repo ใหม่ (private ก็ได้ แต่เว็บที่ publish จะเป็น public เสมอ)
2. แก้ `app.js` บรรทัดบนสุด ใส่ URL ที่ได้จากข้อ 2

```js
API: 'https://script.google.com/macros/s/AKfycb.../exec',
```

3. push ไฟล์ `index.html` กับ `app.js` (ไม่ต้องขึ้นโฟลเดอร์ `backend/`)
4. **Settings → Pages → Source: Deploy from a branch → main / (root)**
5. เปิดเว็บที่ได้ → เข้าด้วย `admin` → เข้าเมนู **ตั้งค่า** → เปลี่ยนรหัสผ่านทันที → เพิ่มผู้ใช้จริง

### 4. ตั้ง trigger ล้าง session (แนะนำ)

Apps Script → นาฬิกา (Triggers) → เพิ่ม → ฟังก์ชัน `cleanupSessions` → รายวัน

## บทบาทและสิทธิ์ (ตรวจที่ฝั่ง Apps Script)

| บทบาท | อ่าน | กรอก/แก้ | ส่งตรวจ | ตรวจสอบ | อนุมัติ | จัดการหัวข้อ/ผู้ใช้ |
|---|:-:|:-:|:-:|:-:|:-:|:-:|
| `admin` | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| `staff` | ✓ | ✓ | ✓ | | | |
| `supervisor` | ✓ | | | ✓ | | |
| `manager` | ✓ | | | | ✓ | |
| `viewer` | ✓ | | | | | |

**เส้นทางสถานะ** — แท็บบนหน้าแรกคือมุมมองของสถานะเหล่านี้

```
ร่าง ──ส่งตรวจ──▶ รอตรวจสอบ ──ตรวจผ่าน──▶ รออนุมัติ ──อนุมัติ──▶ สมบูรณ์
  ▲                    │                        │
  └──── ตีกลับ ◀───────┴────────────────────────┘
```

- แก้ไขได้เฉพาะสถานะ **ร่าง** และ **ตีกลับ** เท่านั้น (admin ข้ามได้)
- ผู้ตรวจ/ผู้อนุมัติ **แก้ข้อมูลไม่ได้** เซ็นได้อย่างเดียว
- ค่าเริ่มต้นห้ามเซ็นเอกสารที่ตัวเองเป็นผู้จัดทำ — เปลี่ยนได้ที่ `ALLOW_SELF_APPROVE` ใน `Code.gs`
- ค่าเริ่มต้น **ส่งตรวจได้แม้กรอกไม่ครบหรือรูปไม่ครบ** — เครื่องหมาย `*` ในฟอร์มเป็นแค่คำแนะนำ
  ถ้าต้องการบังคับให้กรอกครบก่อนส่ง ตั้ง `REQUIRE_COMPLETE_ON_SUBMIT = true` ใน `Code.gs`
- ลายเซ็น 3 ช่อง (จัดทำ/ตรวจสอบ/รับทราบ) ระบบประทับชื่อ+เวลาให้เองตอนกดปุ่ม ไม่ต้องพิมพ์

## เพิ่ม / ลบ / ซ่อน หัวข้อเอง

เมนู **ตั้งค่า → หัวข้อในแบบฟอร์ม** ทำได้ทันทีโดยไม่ต้องแก้โค้ดหรือแก้โครงชีต
เพราะค่าทั้งหมดเก็บเป็น JSON ก้อนเดียวในคอลัมน์ `data_json` ไม่ใช่คอลัมน์ตายตัวแบบ AppSheet

- **ซ่อน** = ไม่แสดงในฟอร์ม แต่ข้อมูลเดิมยังอยู่ครบ — ใช้กับหัวข้อที่เลิกใช้แต่ยังต้องดูย้อนหลัง
- **วัน/เดือน/ปี** และ **ซัพพลายเออร์** ลบไม่ได้ **และซ่อนไม่ได้** เพราะระบบใช้สองช่องนี้ค้นหาและกรอง
  (ซ่อนไว้ = ไม่มีช่องให้กรอก ค่าที่บันทึกจะว่าง แล้วตัวกรองปี/เดือนก็ใช้ไม่ได้ ผลเท่ากับลบทิ้ง) — ดู `PROTECTED_FIELDS` ใน `Code.gs`
- **ลบ** = ลบแค่นิยามหัวข้อ ค่าที่กรอกไว้ยังอยู่ในชีต สร้างหัวข้อรหัสเดิมใหม่ก็กลับมาแสดง
- **ในตาราง** = ให้หัวข้อนี้ขึ้นเป็นคอลัมน์ในหน้าแรก
- ชนิดที่รองรับ: `text` `number` `date` `select` `textarea` `image`

## เรื่องความเร็ว (ปัญหาหลักของ AppSheet เดิม)

| จุด | วิธีที่ใช้ |
|---|---|
| หน้ารายการ | ส่งเฉพาะข้อความ **ไม่ส่งรูปเลย** แสดงแค่จำนวนรูป |
| อัปโหลด | ย่อรูปด้วย canvas ในเครื่องก่อนส่ง (เต็ม 1400px / ย่อ 320px) เหลือไฟล์ละ ~150KB |
| เปิดเอกสาร | ดึงภาพย่อทั้ง 20 รูปด้วยคำขอเดียว (`files.batch`) |
| ภาพเต็ม | โหลดเมื่อกดดูทีละรูปเท่านั้น |

ประมาณการ: 20 รายการ/เดือน × 20 รูป ≈ **70 MB/เดือน** บน Drive

## ข้อจำกัดที่ควรรู้ (ไม่ใช่บั๊ก แต่ต้องรู้ไว้)

1. **GitHub Pages เป็น public** — ป้องกันได้แค่ข้อมูล ไม่ใช่ตัวหน้าเว็บ ใครก็เปิดหน้า login ได้ แต่เข้าไม่ได้ถ้าไม่มีรหัส
2. **CORS ล็อกโดเมนไม่ได้** — Apps Script ไม่ให้กำหนด `Access-Control-Allow-Origin` เอง ใครก็ยิง API ได้ แต่ไม่มี token ก็ทำอะไรไม่ได้ (จึงต้องตั้งรหัสผ่านให้ยาว)
3. **รหัสผ่านใช้ SHA-256 + salt 1000 รอบ** ไม่ใช่ bcrypt เพราะ Apps Script ไม่มีให้ — เพียงพอสำหรับระบบภายใน 3–5 คน แต่ห้ามใช้รหัสซ้ำกับบัญชีอื่น
4. **ลบรูปในฟอร์ม** ตัดการเชื่อมโยงเท่านั้น ไฟล์เดิมยังอยู่ใน Drive (ลบทั้งเอกสารถึงจะลบไฟล์จริง)
   แต่ **กด "เปลี่ยน" รูป** ไฟล์รุ่นก่อนจะถูกเก็บกวาดตอนอัปโหลดครั้งถัดไปของช่องนั้น
   (ตั้งใจให้ช้าไป 1 รุ่น เพราะถ้าลบไฟล์ที่เอกสารยังอ้างถึงแล้วบันทึกไม่ผ่าน รูปจะหายทันที)
5. **ลบแถวใน `sessions` ด้วยมือเพื่อเตะคนออก** ไม่มีผลทันที เพราะ session ถูกแคชไว้ ~25 นาที
   ถ้าต้องตัดสิทธิ์เดี๋ยวนั้นให้ **ปิดใช้งานบัญชี** ในหน้าตั้งค่าแทน (ล้างแคชให้ทันที)
6. **โควตา Apps Script** ~20,000 การเรียก/วัน — ที่ปริมาณงานจริงถือว่าเหลือเฟือ
7. **ยังไม่มี** ออกรายงาน PDF / dashboard กราฟ — เป็นงานเฟสถัดไป ข้อมูลรองรับไว้แล้ว

backend/appsscript.json                   ← วางใน Apps Script
