# พร้อมต์สำหรับ Claude Design — ระบบขายเศษวัสดุเหลือใช้ (TKF)

คัดลอกทั้งบล็อกด้านล่างไปวางใน claude.ai/design
แนบไฟล์ `index.html` กับรูปหน้าจอของเดิมไปด้วย จะได้ผลดีขึ้นมาก

---

## เป้าหมาย

ออกแบบหน้าจอใหม่ให้ระบบบันทึกการขายเศษวัสดุเหลือใช้ของโรงงาน
เป็นเว็บแอปภายใน ใช้ภาษาไทยทั้งหมด ผู้ใช้จริง 3–5 คน
ของเดิมย้ายมาจาก AppSheet ที่ช้ามาก ความเร็วและความชัดสำคัญกว่าความสวย

## ผู้ใช้และบริบทการใช้งาน — ข้อนี้สำคัญที่สุด

- **พนักงานบริการสำนักงาน** ยืนอยู่ลานเศษวัสดุกลางแดด ถือมือถือมือเดียว
  อีกมือถือเอกสารหรือใส่ถุงมือ ถ่ายรูปรถบรรทุก 20 รูปต่อ 1 ใบงาน
  → ปุ่มต้องใหญ่ กดพลาดยาก อ่านออกกลางแดด ใช้นิ้วโป้งมือเดียวได้
- **ผู้จัดการแผนก / ผู้จัดการฝ่าย** นั่งโต๊ะ เปิดคอมฯ ตรวจและเซ็นอนุมัติ
  ต้องเห็นเร็วว่ามีใบไหนรอตัวเองอยู่ และรอมากี่วันแล้ว
- **ผู้ดูแลระบบ** จัดการผู้ใช้และหัวข้อในฟอร์ม

ออกแบบมือถือก่อน (390×844) แล้วค่อยขยายเป็นเดสก์ท็อป (1440×900)

## หน้าจอที่ต้องการ (แยก artboard)

1. **เข้าสู่ระบบ** — ช่องชื่อผู้ใช้ + รหัสผ่าน ไม่มีสมัครสมาชิก ไม่มีลืมรหัส
2. **หน้ารายการ (มือถือ)** — แท็บกรองตามสถานะพร้อมตัวเลขจำนวน,
   ช่องค้นหา, ตัวกรองปี/เดือน (พ.ศ.), รายการเอกสารแบบการ์ด
3. **หน้ารายการ (เดสก์ท็อป)** — ข้อมูลชุดเดียวกันแต่เป็นตาราง
4. **หน้ากรอกเอกสาร (มือถือ)** — 26 ช่องแบ่ง 5 กลุ่ม พับ/กางได้
5. **หน้ากรอกเอกสาร — กลุ่มรูปภาพ** — ตารางช่องแนบรูป สถานะว่าง/มีรูป/กำลังอัปโหลด
6. **แถบปุ่มดำเนินการ** — ปุ่มเปลี่ยนตามสถานะและบทบาท (ดูตารางล่าง)

## เนื้อหาจริง — ใช้ข้อความพวกนี้ ห้ามแต่งใหม่

เลขที่เอกสาร: `20260914-001` (ปีเดือนวัน-เลขรัน)

**5 กลุ่มหัวข้อ (26 ช่อง):**

1. **ข้อมูลรายการ** (6 ช่อง ไม่ใช่รูป) — วัน/เดือน/ปี · ซัพพลายเออร์ · รายการสินค้า ·
   ทะเบียนรถ · ผู้ขนส่ง · ปริมาณน้ำหนัก/จำนวน
2. **ภาพก่อนดำเนินการ** (4 รูป) — รูปหน้ารถ · ข้างรถซ้าย · หลังรถ · ข้างรถขวา
3. **ภาพระหว่างดำเนินการ** (4 รูป) — ภาพ 1–4
4. **ภาพหลังดำเนินการ** (4 รูป) — หน้ารถ · ข้างซ้าย · หลังรถ · ข้างขวา (ดำเนินการเสร็จ)
5. **เอกสารแนบ** (8 รูป) — เอกสารแสดงการจัดการ (กอ.2) · รูปติด waste tag ·
   ใบขออนุมัติขาย ลงนามเสร็จ · ใบชั่งน้ำหนัก · สลิปโอนเงิน · รูปการติดตามระบบ GPS ·
   รูปสินค้าถึงสถานที่ปลายทาง · เอกสารแสดงการจัดการ (กอ.2 ตัวจริง)

**เส้นทางสถานะ:**

```
ร่าง ──ส่งตรวจ──▶ รอตรวจสอบ ──ตรวจผ่าน──▶ รออนุมัติ ──อนุมัติ──▶ สมบูรณ์
  ▲                    │                        │
  └──── ตีกลับ ◀───────┴────────────────────────┘
```

**ปุ่มที่เห็นในแต่ละบทบาท:**

| บทบาท | ปุ่มที่เห็น |
|---|---|
| พนักงาน (staff) | บันทึกร่าง · บันทึกและส่งตรวจสอบ |
| ผู้จัดการแผนก (supervisor) | ตรวจผ่าน · ตีกลับ (แก้ข้อมูลไม่ได้) |
| ผู้จัดการฝ่าย (manager) | อนุมัติ · ตีกลับ (แก้ข้อมูลไม่ได้) |
| ผู้ดูแลระบบ (admin) | ทุกปุ่ม + ลบ + ดึงกลับเป็นร่าง |

ลายเซ็น 3 ช่อง (จัดทำ / ตรวจสอบ / รับทราบ) ระบบประทับ **ชื่อ + เวลา** ให้อัตโนมัติ
ตอนกดปุ่ม ไม่ต้องพิมพ์ ไม่ต้องเซ็นด้วยนิ้ว — ออกแบบให้แสดงเป็นตราประทับ 3 ช่อง

## สิ่งที่ต้องแก้จากของเดิม (ปัญหาที่เจอจริง)

1. ฟอร์ม 26 ช่องยาวมากบนมือถือ ต้องเลื่อนนาน — หา pattern ที่ดีกว่าการพับกลุ่มเฉยๆ
2. ดูไม่ออกว่าเหลืออีกกี่รูปถึงจะครบ — ต้องเห็นความคืบหน้าตลอดเวลา
3. ผู้อนุมัติไม่รู้ว่าใบไหนรอตัวเองอยู่ และค้างมานานแค่ไหน
4. ปุ่มตอนกำลังรอเซิร์ฟเวอร์ (Apps Script ตอบช้า 1–3 วินาที) ต้องบอกสถานะให้ชัด

## ข้อห้าม

- ห้ามวาดแถบสถานะ iOS ปลอม (เวลา แบตเตอรี่ wifi) หรือคีย์บอร์ดปลอม
- ห้ามใช้อีโมจิเป็นไอคอน — ใช้ SVG เส้น ขนาด 20/24px สไตล์เดียวกันทั้งระบบ
- ห้ามพื้นหลังไล่เฉดสี — เป็นเครื่องมือทำงานโรงงาน ไม่ใช่หน้าขายของ
- ห้ามเปลี่ยนสีประจำสถานะ 5 สีข้างบน
- ห้ามใส่กราฟหรือ dashboard — ยังไม่มีในระบบ
- ปุ่มบนมือถือสูงอย่างน้อย 44px
